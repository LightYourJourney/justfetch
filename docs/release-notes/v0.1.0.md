# justfetch v0.1.0 — pre-release

A compact, offline Rust CLI that prints real local system information: OS, host, kernel, uptime, CPU, memory and shell, with a responsive ASCII layout and structured JSON.

**This is a pre-release.** It is on GitHub only. Nothing has been published to crates.io, and the platform coverage below is not the full matrix the project intends to verify before its first real release.

Each archive holds the binary, `LICENSE` and `README.md`. Extract it and put `justfetch` somewhere on your `PATH`.

## What has actually been verified

Being in the table above means the archive was built. It does not mean anyone has run it there. Those are different claims and this project keeps them apart.

**Executed on real hardware or a native runner:**

- macOS arm64 — exercised locally on an Apple M3 throughout development.
- Linux x86-64 (Ubuntu 24.04) — the native CI job runs the binary and reads its JSON output on every push.
- Windows x64 (Server 2025) — the same native CI job.

**Built but not executed on the target:**

- **macOS x86-64 (Intel).** Cross-compiled on an Apple Silicon runner; it has never been run on Intel hardware. The closest evidence is Rosetta 2 on Apple Silicon, where this archive's memory figure agrees with the native arm64 build to within a few MiB. An earlier build of the same archive read memory four times too low there, and that is worth knowing about: Rosetta hands a process a 4096-byte page size while the Mach counters it reads are in the host's 16384-byte pages, so pairing the two silently understated memory by exactly the page-size ratio. The archive attached here contains the fix, which asks the host for its page size instead of asking the process. On Intel hardware the two agree, so the change should be invisible there — reasoning again, not a measurement.
- **Linux ARM64.** Built natively on an ARM64 runner, which only proves it compiles and links there.

**Not tested at all:** WSL, containers, any distribution other than Ubuntu, and every hardware-sensitive path the compatibility matrix still marks as compile-only.

## Verify your download

```sh
sha256sum -c SHA256SUMS --ignore-missing
```

`--ignore-missing` is not optional in practice: `SHA256SUMS` covers all five archives, so without it the four you did not download are reported as failures and a perfectly good download looks corrupt. `shasum -a 256 -c SHA256SUMS --ignore-missing` behaves the same way.

## These binaries are not signed

There is no Apple Developer certificate and no Windows code-signing certificate behind this project, so neither platform will vouch for the download.

- **macOS** — a browser download is quarantined and Gatekeeper will refuse to open it. Either fetch it with `curl` (which sets no quarantine attribute) or clear it manually: `xattr -d com.apple.quarantine justfetch`.
- **Windows** — SmartScreen will warn about an unrecognized publisher. Choosing to keep the file is a decision about trust, and the checksum above is the only evidence this project can offer for it.

## Requirements

No runtime dependencies and no configuration. It does not use the network, does not require administrator access, and does not call other fetch tools.

## Feedback

Bug reports are most useful when they include the platform, the exact command, and the `--format json` output. If a field reports an error or an unavailable state instead of a value, that is working as designed — the reason is in the JSON — but it is also exactly the kind of report worth filing.
