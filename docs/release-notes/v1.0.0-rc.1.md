# justfetch v1.0.0-rc.1 — release candidate

A compact, offline Rust CLI that prints real local system information: OS, host,
kernel, uptime, CPU, GPU, memory, swap, disk, battery, display (opt-in),
per-manager package counts, desktop session (Linux), locale, shell, terminal and
local addresses — in a responsive terminal layout or as one JSON document.

**This is a release candidate, not a final release.** It is on GitHub only.
Nothing has been published to crates.io. The runtime evidence below covers
macOS on Apple Silicon; the Linux and Windows binaries are built by CI and their
test suites run there and the packaged binary is smoke-tested, so the collectors
do execute there; their output has not been compared with those platforms' own
tools, and WSL is untested.

every archive.

## What changed since v0.1.0

- Seven fields became seventeen. New: GPU, Battery, Display, Packages, Desktop,
  Locale; the earlier additions were Swap, Disk, Terminal and Local IP.
- Module selection, ordering and labels, with a TOML configuration file,
  `justfetch init` and `justfetch doctor`.
- Six colour themes, four layouts, custom theme and logo files.
- `--privacy`, which withholds the user name, host name and local addresses.

## What has actually been verified

| Target | Build | Tests | Binary run |
| --- | --- | --- | --- |
| macOS ARM64 | Yes | Yes | Yes, interactively on a MacBook Air (Mac15,12) |
| macOS Intel | Yes (cross-compiled) | — | Yes, under Rosetta 2 on this Apple Silicon host — execution, but not Intel hardware |
| Linux x86-64 | Yes (CI) | Yes (CI) | Only through CI's packaged-binary smoke test |
| Linux ARM64 | Yes (CI) | **No** — the CI test matrix is x86-64 only; this target is built and its archive smoke-run | Only through that smoke test |
| Windows x64 | Yes (CI) | Yes (CI) | Only through CI's packaged-binary smoke test |

GPU, Battery, Display, Packages, Desktop and Locale have been compared against
`system_profiler`, `pmset`, `brew list` and `defaults read` on macOS. On Linux
and Windows they compile and their parsing helpers are unit-tested, but the
collectors themselves have not been cross-checked against those platforms' own
tools. `docs/compatibility.md`
records this per module.

## Installation

From a checkout of this repository:

```sh
cargo install --path . --locked
```

This exact command was run on the release candidate: it installs
`justfetch 1.0.0-rc.1` and the installed binary emits a valid document.

The archives above need no toolchain: extract one and put `justfetch` on your
`PATH`. There is no crates.io release, Homebrew formula or Scoop manifest yet;
`packaging/` holds the draft manifests, not published ones.

## Checking it on your own machine

`scripts/verify-macos.sh`, `verify-linux.sh` and `verify-windows.ps1` run the
binary beside the platform's own tools and print a verdict per module — `match`,
`mismatch`, `uncomparable` or `unsupported`. They are read-only and print no
identifying values. If you see a `mismatch`, that is a bug worth reporting with
the table attached. `scripts/verify-wsl.sh` checks the WSL labelling and the
states that should have no value.

## Known limits

- Swap is `unsupported` on Windows: no permitted API exposes page-file usage.
- `display` is not in the default module list; its query costs tens of
  milliseconds on macOS. Select it with `--modules display`.
- The macOS display row reports the current mode's logical size, not the panel's
  native resolution.
- RPM and Nix package counts are `unsupported`, as are winget and, by design,
  Desktop on macOS and Windows.

## Checksums

Verify an archive before running it:

```sh
shasum -a 256 -c SHA256SUMS        # macOS
sha256sum -c SHA256SUMS            # Linux
Get-FileHash .\*.zip -Algorithm SHA256   # Windows
```
